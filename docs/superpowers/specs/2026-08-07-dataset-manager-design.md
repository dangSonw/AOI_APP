# Dataset Manager Design Specification

**Date:** 2026-08-07  
**Author:** AI Agent  
**Status:** Approved for implementation  
**Scope:** Full dataset management — file-based storage in `data/datasets/`, backend API, frontend Dataset tab with image viewer

---

## 1. Overview

The AOI system needs a Dataset manager to organize reference images (golden samples), captured images, and custom training datasets. Unlike the Inspection Database (PostgreSQL records), datasets are **file-based**: folders on disk under `data/datasets/` with a `metadata.json` descriptor. The backend provides a REST API over these folders; the frontend provides a visual file manager with image viewing.

**Key design decisions:**
- No database tables — datasets are filesystem directories with JSON metadata.
- Images stored as files on disk; metadata.json auto-generated/updated by backend.
- Backend uses `pathlib` with relative paths from `PROJECT_ROOT` (portable across WSL, Jetson Nano, any Linux).
- Frontend talks only to backend API — never accesses filesystem directly.
- Upload uses `multipart/form-data`; download/export uses streaming ZIP.

### 2.1 metadata.json Schema

```json
{
  "name": "golden-samples",
  "description": "Golden reference images for Rev C mainboard",
  "createdAt": "2026-08-07T10:30:00Z",
  "updatedAt": "2026-08-07T14:22:00Z",
  "categories": [
    { "name": "top-view", "imageCount": 2, "totalSizeBytes": 2156800 },
    { "name": "bottom-view", "imageCount": 1, "totalSizeBytes": 1078400 }
  ],
  "totalImages": 3,
  "totalSizeBytes": 3235200
}
```

- `metadata.json` regenerated by scanning actual directory contents after every mutation.
- Frontend reads metadata through API, never directly.

### 2.2 Naming Constraints

| Entity | Rule | Example |
|--------|------|---------|
| Dataset name | kebab-case, 1–64 chars, `[a-z0-9][a-z0-9-]*[a-z0-9]` | `golden-samples` |
| Category name | kebab-case, 1–64 chars, same pattern | `top-view` |
| Image filename | `[a-zA-Z0-9_-]+\.(png|jpg|jpeg|bmp|tiff)`, max 128 chars | `img001.png` |

Names must not contain `..`, `/`, `\`, null bytes, or hidden-file prefixes.
Backend validates and rejects unsafe names with 422.

### 2.3 Supported Image Formats

PNG (preferred, lossless), JPEG/JPG, BMP, TIFF/TIF.
Max single file: **50 MB**. Max upload batch: **100 files** per request.

## 3. API Endpoints

All endpoints require `Authorization: Bearer <token>`. Prefix: `/api/datasets`.

### 3.1 Dataset CRUD

| Method | Path | Description |
|--------|------|-------------|
| GET | `/api/datasets` | List all datasets with metadata |
| POST | `/api/datasets` | Create dataset (JSON body: name, description) |
| GET | `/api/datasets/{name}` | Get single dataset metadata + categories |
| PUT | `/api/datasets/{name}` | Update dataset (rename, description) |
| DELETE | `/api/datasets/{name}` | Delete entire dataset (folder + all images) |

### 3.2 Category CRUD

| Method | Path | Description |
|--------|------|-------------|
| POST | `/api/datasets/{name}/categories` | Create category subfolder |
| PUT | `/api/datasets/{name}/categories/{category}` | Rename category |
| DELETE | `/api/datasets/{name}/categories/{category}` | Delete category + images |

### 3.3 Image Operations

| Method | Path | Description |
|--------|------|-------------|
| GET | `/api/datasets/{name}/categories/{category}/images` | List images in category |
| POST | `/api/datasets/{name}/categories/{category}/images` | Upload images (multipart) |
| GET | `/api/datasets/{name}/categories/{category}/images/{filename}` | Serve image file |
| DELETE | `/api/datasets/{name}/categories/{category}/images/{filename}` | Delete single image |
| PATCH | `/api/datasets/{name}/categories/{category}/images/{filename}` | Rename image |
| POST | `/api/datasets/{name}/categories/{category}/images/{filename}/move` | Move to another category |

### 3.4 Bulk / Import / Export

| Method | Path | Description |
|--------|------|-------------|
| POST | `/api/datasets/{name}/import-captures` | Copy images from `data/captures/` into dataset |
| GET | `/api/datasets/{name}/export` | Download dataset as ZIP (streaming) |

### 3.5 Captures Browser

| Method | Path | Description |
|--------|------|-------------|
| GET | `/api/captures` | List available capture images for import |

## 5. Backend Architecture

### 5.1 Files to Create

| File | Responsibility |
|------|----------------|
| `backend/app/api/datasets.py` | API router, all dataset endpoints |
| `backend/app/services/dataset_service.py` | Filesystem operations, metadata management |
| `backend/app/schemas/dataset.py` | Pydantic request/response schemas |

### 5.2 Service Layer Rules

- All paths resolved with `pathlib.Path` relative to `PROJECT_ROOT / 'data' / 'datasets'`.
- **Path traversal defense:** validate every name segment against `^[a-z0-9][a-z0-9-]*[a-z0-9]$` and reject `..`, absolute paths.
- `metadata.json` regenerated by scanning actual directory contents after every mutation.
- Image dimensions read with Python `struct` module from PNG/JPEG headers (no PIL dependency). If header parsing fails, set `widthPx`/`heightPx` to null.
- ZIP export uses `zipfile.ZipFile` with `ZIP_DEFLATED` and streams via `StreamingResponse`.
- File writes use atomic temp-file + `os.replace()` pattern (consistent with memory.md rule).
- Max file size enforced by reading `Content-Length` header and rejecting oversized uploads before writing.

### 5.3 Settings Addition

Add to `backend/app/config/settings.py`:

```python
datasets_data_directory: str = 'data/datasets'

@property
def datasets_data_path(self) -> Path:
    return PROJECT_ROOT / self.datasets_data_directory
```

| Export ZIP | Click [Export] on dataset | `GET .../export` |
| Delete dataset | Context menu with confirmation | `DELETE /api/datasets/{name}` |

## 7. Security

- All path segments validated against allowlist regex before filesystem access.
- Path traversal (`../`) rejected before any operation.
- File content validated: first bytes checked for image magic numbers (PNG: `89 50 4E 47`, JPEG: `FF D8 FF`, BMP: `42 4D`, TIFF: `49 49` or `4D 4D`).
- Max file size 50 MB enforced server-side.
- Backend serves images through API endpoint (not static mount) to enforce auth.
- Delete operations require confirmation dialog in frontend.

## 8. Compatibility Notes

- **WSL:** All paths use forward slashes via `pathlib`. No Windows path handling.
- **Jetson Nano:** No PIL/Pillow dependency for basic operations. Image dimension extraction uses lightweight struct-based header parsing. Graceful fallback if parsing fails.
- **Atomic writes:** Temp file in same directory + `os.replace()` for metadata.json.
- **File permissions:** Directories 0o755, files 0o644.

## 9. Out of Scope

- Image annotation (drawing bounding boxes).
- AI model training pipeline integration.
- Automatic labeling or classification.
- Image preprocessing (resize, augment, normalize).
- Version control for datasets.
- Multi-user concurrent editing locks.
- Database-backed metadata (intentionally file-based for portability).
